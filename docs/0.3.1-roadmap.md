# v0.3.1 roadmap

Cross-input reruns and browser/OS matrix labels are deferred by the release scope
decision. v0.3.0 refuses repeated scenario locations across inputs, while retaining
disjoint shards and retries within one input. No rerun flag or configuration/API
field is shipped in v0.3.0.

Design this together before adding a public API:

- Explicit labels distinguish independent browser/OS cells. A pass in one cell
  must never rescue a failure in another.
- Ordered reruns form chains within one label, with timestamp ordering verified
  independently of argument order.
- Revision checks prevent a rerun from rescuing an execution of different code.
- Missing or conflicting ordering, label and revision evidence produces an
  actionable refusal, without guessing intent from duplicate scenarios.
- Fixtures and runtime mutants cover unrelated runner failures, strict/flaky
  policies, reordered inputs, incomplete chains and all public output surfaces.

The unfinished experimental implementation is parked outside the release tree;
it is not a supported feature or an approved design.

Remaining presentation and integration follow-ups (no failure is suppressed):

- Add context variants for preparation and directory publication APIs as an
  additive API change, with cancellation coverage.
- Keep gathering real cucumber-js JSON text-embedding captures; the current
  hand-built fixture remains explicitly unconfirmed in the support matrix.
