## Root cause (why greener-than-evidence keeps reappearing)

"Outcome" is still computed in several independent places: `combine()` (report/model.go), `ScenarioOutcomes`/`RunStatus`
(report/outcomes.go, cucumber, cucumbermodel), known-issue matching (model.go:391-423), gates (summary vs exit code),
and the runner-success overlay. The r12 evidence floor only reconciles **counts** on the **rendered page**, so any of the other
places can still disagree, and a per-scenario wrong outcome is "represented" as long as the failure appears somewhere (e.g. in attempts).

**Required fix: one outcome authority.** A single function (e.g. `internal/outcome.Decide(model, opts, runnerSuccess, gates)`) returns,
per scenario, the final status + reason (retry-rescued / known / gated / runner-failed) and the run verdict + tone + exit-gate. Page,
summary.json, summary.md, CSV, rerun.txt, `-fail-on-unexpected`, gates, `report.ScenarioOutcomes`, `cucumber.RunStatus` and
`PreparedRun` must all read from it; nothing else may derive a status. The evidence floor then checks **per-scenario invariants**
against the raw scan, not counts:
1. every raw non-passed result belongs to a scenario whose final status is non-green, OR is rescued by an attempt whose every result passed (later attempt), OR is exactly the annotated known step with all other non-passed results skipped;
2. run tone may be `ok` only if (1) holds for all scenarios, no gate failed, and runner success is not false;
3. any violation is an explicit error naming uri:line.
Test: stub/disable each individual rule (retry rescue, known match, background fold, gate) and assert the floor raises at runtime.
