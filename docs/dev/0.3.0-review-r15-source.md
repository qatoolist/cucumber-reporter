## Root cause this round

Each new rule ("explained runner failure", "reruns rescue", "inferred retry failure", "known across attempts", "zero-attempt
runner failure") was added to the decision logic, and the safeguard either reused the same logic or didn't check that rule at
all. So disabling the rule, or feeding input the rule mishandles, goes straight to green.

Required fixes:
1. **The safeguard must be an independent oracle.** `internal/evidence` derives these straight from the raw scan, and `report` must not share code with it:
   - the runner signal for each stream;
   - the attempt count for each case;
   - each case's final non-passed results;
   - which inputs are cross-input repeats.

   It then checks these invariants, with no imports from the decision code:
   - (a) a stream with `success:false` must give a fail verdict, unless a scenario *from that stream* is still failed in the final report;
   - (b) a case with a raw attempt count above 1 must show a non-passed attempt in the report;
   - (c) a cross-input repeat without `Reruns` is a reporter bug;
   - (d) a known-issue rescue must match position and text in a separate, simpler matcher.
2. **Monotonicity property test.** Over every fixture and capture: adding a scenario whose own final status is non-green, or adding an input, must never make the verdict tone greener. Removing a failing-then-rescued scenario must never make it redder. A2-H2 breaks this today.
3. **Mutant gate.** Make `mutations.py` plus the A2 N1–N8 mutants a CI gate (it is already in CI). Every rule added from now on needs a mutant that the runtime floor kills, in both JSON and Messages.

### Manual Comet checklist (D2, about 10 minutes; use a plain retry report and the attach report)
1. Jump to step: click it, scroll away, click it again → the page scrolls back both times.
2. View evidence goes somewhere different from Jump to step: an attachment opens and gets focus.
3. Collapse that attachment and click View evidence again → it re-opens.
4. Plain retry report: the View evidence count is 15, not 20.
5. Retry scenario: select Attempt 1, collapse Attempt details, click View evidence → the right attempt opens.
6. Expand all → everything opens. Collapse all → only the headers remain, and a 1-line error must not look faded.
7. After Collapse all, Tab never reaches Copy, Save or Find. Expand an attachment → they become reachable.
8. JSON attachment: Find shows raw text, and the Tree/Raw switch should then say Raw.
9. Scenarios list: press Space on the "Failed" chip, then Tab → focus continues from the chip.
10. Table: sort with the keyboard, then Tab → focus stays in the header.
11. Dashboard: press Enter on a legend item, then Tab → focus stays in the legend.
12. Press `/`, search a step on the current scenario page, press Enter → it is revealed. Repeat once.
13. Press `?` → the shortcuts dialog opens; Esc closes it and returns focus.
14. Full-screen error: Tab stays inside the dialog; Esc returns focus to the Full screen button.
15. Print → Failures only → Preview, then Executive summary → the preview updates in place.
16. Below 1024px with the menu closed, Tab from the top must not enter the navigation. Opening the menu and pressing Esc returns focus to the menu button.
17. Collapse navigation with the keyboard → focus stays on the button and its label flips.
18. A scenario row → Back to list → the scroll position is restored. Also try browser Back.
19. Problems only, then a sidebar attachment link on a passed step → the step shows and the switch state matches.
20. An error over 1,000 lines: keep pressing "Show next 1,000 lines" → the button greys out at the end.
