# v0.3.0 whole-change review response (round 7)

This is a historical response. The [round-8 follow-up](0.3.0-review-r8.md) supersedes
its identity, hook-support and history-budget behavior; use the current guide for contracts.

Status: implemented for another whole-change review; **not approved for tagging**.
Browser, print and Chromium/Firefox/WebKit CI suites remain pending. No local browser
was launched for this revision, and no commit, push, release or tag was created.

The three requested regression families were added before implementation. They exposed
unscanned evidence/metadata, shard-order reference changes and format-dependent
outline identities. Fixes then changed the shared contracts instead of adding more
MIME exceptions or another CLI-only attempt merger.

## Must-fix findings

| Finding | Disposition and regression coverage |
| --- | --- |
| H1 — format/subset identity | Fixed. Enhanced fallback identity is URI + source/example-row line + name for both formats, independent of outline spelling and other rows. The format-parity/outline-subset test uses both actual parsers and the library Messages-attempt path. |
| H2 — shard-order references | Fixed. Enhanced navigation incorporates the full normalized URI, rather than collision numbering dependent on traversal. Permutation/subset tests check IDs and metadata binding. Run hooks use the stable logical input name; parents and argument order do not identify a stream. |
| H3 — dropped legacy hooks | Fixed for scenario-level before/after hooks: failures, duration and evidence fold into the owning scenario. CLI tests require gate exit 3, visible hook evidence and rerun selection. Step-local/nested legacy hooks are refused in enhanced mode pending an ordering contract. Plain parsing remains compatible. |
| R1 — media allowlist | Fixed. All bodies except known binary media types are inspected. Tests cover HTTP, CSV, PEM, custom types and existing text types. |
| R2 — invalid UTF-8 | Fixed. Literal regex matching operates on bytes; a Latin-1 log cannot bypass matching of ASCII secrets. There is no charset transcoding or binary scanning claim. |
| R3 — metadata leaks | Fixed. Display/config strings, worker IDs, explicit identities and history scopes are masked consistently. The planted-field/output test scans HTML, sidecars, summaries, CSV/Markdown, history and ZIP members; a separate attempt-merge test covers runner workers. Scope matching uses masked keys. |
| R4 — structural mutation | Fixed. Structural enums, computed navigation/comparison references, MIME types and timestamps remain structural. Tests match run-hook/status text and comparison slugs without changing counts or links. |
| R5 — JSON headers | Fixed. Header names also match JSON keys case-insensitively. They use a separate rule set; malformed typed JSON only fails closed when `jsonKeys` is configured. |
| R6 — forged analysis | Fixed. CLI options refuse `analysis` regardless of supplied value. Tests require exit 1 and no artifacts. Go callers retain the trusted rendering API. |
| M1 — annotation offsets | Fixed. Both annotation `step` and `outcomes[].step` are remapped over prepended Background/before-hook results. The CLI regression keeps a known failure out of the unexpected gate. |
| M2 — lost history scopes | Fixed. Analysis filters by scope; persistence retains all scopes, with retention applied independently. Three alternating-environment runs preserve earlier staging and production observations. |
| M3 — unreadable history | Fixed. Archived scenarios are slimmed, JSON is compact, and writer/reader share a 64 MiB limit. Budget pruning emits a diagnostic and preserves every scope's newest snapshot; if those cannot fit, writing is refused. The large-suite retention test round-trips the archive. |
| M4 — duration gates | Fixed. Both outcomes must pass, baseline duration must be positive, and absolute increase must reach 100 ms before percentage gating or “slower” classification. Zero/skipped/tiny-baseline tests cover the original false positives. |
| C1 — duplicate sidecars | Fixed. Directory writers share content-addressed deduplication, retaining exclusive-create failures for positional names. Tests cover repeated/distinct binary evidence and positional collision refusal. CLI options also refuse Go-only `bundleAttachments`; use enhanced `-bundle`. |

## Should-fix findings

| Finding | Disposition |
| --- | --- |
| R7 — JSON inside strings | Deferred and documented. Key rules inspect JSON structure, not a second JSON document encoded inside a string. Mask the outer key (such as `body`) or use a literal secret pattern. A contract test covers this boundary and the outer-key workaround. Recursive decoding would need depth, malformed-inner-value and escaping contracts. |
| R8 — regexes spanning JSON tokens | Documented contract, with regression test. Patterns match decoded individual keys/values/scalars; use `jsonKeys` for key/value syntax. This preserves valid JSON and untouched formatting. No claim of matching a regex across serialized JSON tokens remains. |
| P1 — quadratic processing | Fixed in the identified paths. Retry completion uses maximum-attempt maps; the library owns one indexed attempt merge; history samples aggregate by identity instead of scanning every scenario for each current row. Large history and 20k-scenario UI checks cover scale, without a machine-dependent two-second guarantee. |
| P2 — duplicated final evidence | Fixed for serialized HTML: final attempts reference scenario steps, and browser-free JS tests verify resolution. CLI whole-file buffering, diagnostic reparsing and model copying still affect peak memory and are documented. |
| M7 — identity override follows moved line | Corrected documentation. An explicit identity preserves historical matching only when its metadata navigation key is updated after a line move. The moved-line comparison test supplies that updated key. No automatic relocation is promised. |
