## Root cause: nothing enforces "never greener than the evidence"
Every round has fixed the false greens one at a time. Each new transformation (folding, dropping, merging, lenient parsing) can silently discard a failure. Add **one independent guard** instead of relying on each transformation being right:

**Evidence floor (mandatory, both modes, validate too):**
1. **A dumb, separate scanner.** Write a deliberately simple scanner that walks the **raw decoded input** before any folding, merging or leniency. It records every result status it sees: steps, hooks at every level, Background elements, every attempt, and duplicate-key values (take the *worst*, not the last). For Messages, it also records `testRunFinished.success`.
2. **Reconcile against the final model.** After building the final model:
   - Every raw non-passed result must be **accounted for**. It is either shown in the final model (as a scenario, attempt, hook or folded Background step), or it belongs to a retry whose **final attempt strictly passed** (per Cucumber retry semantics). There is no other exception.
   - If anything is unaccounted for, the verdict cannot be green. Fail closed with a diagnostic ("N failures in the input are not represented; this is a reporter bug") and a fail-tone verdict.
3. **Runner signal.** If the runner said `success:false` (Messages) and the computed verdict is green, downgrade it to a non-green "Runner reported failure" and give the reason.
4. **Property test.** Mutate every fixture by inserting a failure at random positions: a step, a hook, a Background, an attempt, a duplicate key, a trailing element. Assert the verdict is never Passed or Passed-with-known unless the inserted failure is shown, or sits in a rescued retry.

This turns the whole class of bug into a loud reporter error instead of a false green.
