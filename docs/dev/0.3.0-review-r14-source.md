## Correction to my round-13 brief (W-H3)

I recommended treating a later input's execution of the same uri:line as a later attempt, by default. **That was wrong.** Nothing in the input separates a rerun from a parallel or matrix shard of the same suite. So the headline enhanced workflow, `cr -enhanced shard-a shard-b` (README:137), now turns a real failure into "Passed (1 flaky)". Reruns across inputs must be **explicit opt-in**. See X-1.
