Three independent reviewers checked round 10:

- **N:** UI, PDF, history and release engineering.
- **O:** realistic output from 8 runners (cucumber-jvm 7, cucumber-ruby 9, cucumber-js 10/12 JSON and Messages, Godog 0.14, Reqnroll 2/3, pytest-bdd 7, behave 1.2.6) in all modes, checked against ground truth.

The conductor re-ran the items marked **[verified]**; the others were reproduced by a reviewer.

## Status
- **Round-10 items:**
  - B1 is fixed: a hook failure is now a plain-mode failure, its error and evidence are shown, and validate agrees.
  - K-H1 is fixed: 50k colliding IDs dropped from 192 s to 0.78 s, with byte-identical IDs.
  - K-H3, K-H5, K-H6, K-H7, J-P1 and J-1 are fixed, and so are L-M2 through L-M7 apart from the regressions listed below.
- **All 20 earlier conductor repros pass.**
- **v0.2.0 API:** a compile check of all 196 identifiers with exact signatures passes, so nothing was removed.
- **Real runners:** O found **no wrong verdict** across 17 accepted fixtures from real-runner formats. Plain and enhanced agree, the counts match the per-scenario statuses, and hook and Background failures are never shown as Passed.
- **Gates:** race tests, vet, fmt, fuzzing, the node tests (9/9) and asset/CSP parity all pass.
- **Not ready to tag:** the plain-mode folding added in round 10 created **a new false green and several plain-mode compatibility regressions**. There are also two regressions next to the UI and PDF fixes, and two real-runner data-loss gaps.

## Root cause for this round: plain mode has two folding branches with different rules
`fold.go` takes one path when a scenario has a Background and another when it doesn't. The two paths differ in:
- which hooks are kept;
- how steps are numbered;
- how "has own steps" is computed.

So plain output now depends on whether a Background exists. **Write down the plain-mode compatibility contract and enforce it with a differential test against v0.2.0:**
- **Contract:**
  1. Plain mode shows what v0.2.0 showed, PLUS two things:
     - (a) non-passed hooks are counted and shown, with their error and evidence;
     - (b) a separate Background element is folded into the scenario that follows it.
  2. **Passing hooks stay hidden in every case**, as in v0.2.0, with or without a Background.
  3. Annotation `step` in plain mode keeps **v0.2.0 numbering**: the position in the element's own `steps[]` array. That includes cucumber-js inline hidden hooks, which v0.2.0 counted. It excludes the jvm/ruby `before`/`after` arrays and Background steps, which were never in `steps[]`.
     - This numbering never depends on a hook's outcome.
     - Enhanced mode keeps own-step numbering. Document the difference.
  4. Scenario navigation IDs stay byte-identical to v0.2.0. A folded Background element **keeps its ID slot**: compute IDs as if it were still an element, so later IDs (especially line-less `-L0-N`) don't shift. An annotation that targets an old Background ID gets a clear error: "Background results are folded into the next scenario; annotate <id>".
  5. Inputs v0.2.0 rendered keep rendering, apart from documented exceptions.
- **Test (compatibility harness):**
  - Build v0.2.0 from the tag in the test and run it over a fixture corpus: `revK-work/fx`, `revO-work/runners`, `revM-work/{bgh,hk,js,opt}` and `testdata/synthetic`.
  - For each fixture, compare the data block against the current plain output.
  - Allow only the contract differences (a) and (b), listed per fixture in an expectations file. Fail on any other difference.
  - If building the old tag in tests is too heavy, generate the v0.2.0 outputs once with a script and commit them as goldens.

## Tests (first, and watch them fail)
1. **Compatibility harness** (above): v0.2.0 versus the current plain output over the fixture corpus, allowing only contract differences.
2. **No false greens:** a step-less scenario with or without a Background or hooks is Undefined in both modes. Fold the following into the existing "never Passed over a failure" property:
   - every fixture's verdict family against `truth.json`;
   - O's `revO-work/runners/*/truth.json` and `check.py`.
3. **Plain numbering stability:** the same options file resolves identically whether the cucumber-js inline After hook passes or fails.
4. **Background ID slot:** line-less input with a Background keeps v0.2.0 IDs for the scenarios. An annotation on the old Background ID gets the clear error.
5. **Public API consumer test:** go-cmp on `Parse` output; `go doc` shows the fields and methods; `%T` is `cucumber.Feature`.
6. **Print preview:** the scope survives `afterprint` while on `#/print`.
7. **gs fork:** a wrapper script that forks a sleeping child; cancel returns within WaitDelay + ε.
8. **Runner `output`:** the jvm and ruby fixtures show their log text as attachments, and redaction masks secrets in it.
9. **Add O's real-runner fixtures to the repo** (`testdata/runners/<runner>/` with `truth.json`) and run them in CI. Flag the ones O was unsure about (cucumber-js base64 text embeddings, ruby `--retry`) until they're confirmed with captured output.
