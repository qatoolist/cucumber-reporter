## Shared contracts

Both adapters use `foldScenarioSteps` to construct execution order and assign
`Origin` (`hook`, `background`, `own`) and 1-based `OwnIndex`. Input annotations map
from own-step indices to execution positions; hooks cannot be targeted by an own-step
annotation. Legacy hook arrays and Messages AST origins feed that same map.

Computed identifiers are structural. Current explicit identities are redacted once
before comparison; imported scenario/issue identities stay as stored. Generated run
IDs are marked and validated, so broad patterns cannot collapse repeated executions.

Plain identities use normalized URI/name, outlines use URI/name/row line, and run
hooks retain their existing synthetic-source rule. **Summary schema is 3**, rather
than retaining schema 2 as suggested in the brief's README note. This deliberate
extra bump prevents incompatible round-7 identities from silently entering a new
comparison. Regenerate schema-1/2 development summaries; do not relabel them.
Plain options schema 2, plain navigation and plain golden output remain unchanged.
